# R-001 closure — measurement against the current tree (2026-10-27)

**Purpose:** decide R-001 on current facts. Its expiry is 2026-11-18, and its own Condition 5 says to
*"close as remediated when the Next.js 15 migration lands"* — so the question is whether that has
happened, not whether to renew.

## Measured

Installed tree: **`next@15.5.28`**, `react@19.3.1` (the R-007 migration, released 2026-10-24).

```
npm audit --json  ->  metadata.vulnerabilities
  { info: 0, low: 0, moderate: 20, high: 7, critical: 1, total: 28 }
```

**Advisories naming `next` directly: 0.** R-001 was an acceptance of **25 advisories against
`next@14.2.35`**; on 15.5.28 that set is gone. `next` still appears in `npm audit` output, but only as
a **carrier for a transitive `postcss` advisory** — not an advisory against `next` itself.

**R-001 is therefore closed as remediated, not renewed.** The condition it was accepted under was
"until the Next.js 15 migration lands", and it landed.

## What the tree carries instead

The 28 advisories are a *different* set, and the register had no entry for them — which is why R-001
being closed is not the same as the dependency surface being clean.

| --- | --- | --- | --- | --- |
| `tar` | **critical** (npm aggregate; advisory is high) | no | **dev only** — sole dependent is `node_modules/supabase`, a **devDependency** CLI | hardlink path traversal; **not in the deployed bundle** |
| `zod` | high | **yes** (`^3.22.4`) | **unused** | imported nowhere in the repo (see below) |

| `@solana/*` wallet adapters | mod | mostly yes | runtime | `@solana/web3.js` chain; no fix available for several |

### The one clean win: `zod` is declared and never used

`zod` is a **direct runtime dependency** (`^3.22.4`) carrying a **high** advisory — *"Zod can exhaust
memory while validating oversized constrained collections"* — and:

```
grep -rn 'from "zod"' --include=*.ts --include=*.tsx --include=*.mjs --include=*.js . | grep -v node_modules
  (no matches)
```

It is **imported nowhere** in the application, tests, or scripts. The recommended action is therefore
not "upgrade to zod 4" (a semver-major) but **remove the dependency**, which deletes the advisory and
one unused supply-chain edge with it. That is a separate dependency change and is not made here.

## Not verified

- Whether `uuid`'s advisory is reachable through any path this app actually takes. It is direct and
  runtime, so it is not dismissed here — it is unassessed.
- Whether any `@solana/*` moderate advisory is reachable in the browser; these are the wallet stack and
  several report **no fix available**.
- No advisory in the current set was reproduced experimentally. Unlike R-002, none was characterised by
  running a trigger — the table above is a reachability classification from the dependency graph, not a
  proof.
