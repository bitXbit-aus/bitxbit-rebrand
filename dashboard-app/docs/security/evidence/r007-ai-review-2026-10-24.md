## 1. Reviewers and method

Two models from **different labs**, in **separate API calls**, each given the **identical** bundle and
the same adversarial prompt. Neither shared context with the implementer. Raw responses are retained
verbatim alongside this file.

| Reviewer | Underlying model | Vendor | Call |
|---|---|---|---|
| A | `anthropic/claude-sonnet-5.5` | Anthropic | separate call, own context |
| B | `openai/gpt-6.1-sol-pro` | OpenAI | separate call, own context |

**Route and a failed first attempt, recorded rather than glossed.** The first attempt used two
direct vendor APIs; **both failed on the providers' side, not on our code** — Google returned
`429` (free-tier quota, limit 0 for that model) and Moonshot returned `429` (account suspended,
insufficient balance). Both are recorded in `../evidence/` scratch outputs; neither produced a
review. The reviews below were then run via OpenRouter, which is a **router, not a model** — the two
underlying models are still from different labs, which is what "genuinely different" requires.

**Bundle:** the full diff of the reviewed SHA plus the key source files read **at that SHA**
(`git show <sha>:<path>`), with an explicit adversarial prompt and a JSON output contract.
A secret scan runs before any bundle leaves the machine and refuses to proceed on a match
(**0 hits on every run**).

**Method limits, stated plainly.** These are single-pass reviews: the models read a bundle, they do
not run tools, execute tests, or query the deployment. Their findings were therefore **re-measured by
the implementer** before being acted on — and several did not survive that (see §4). A single-pass
review is not equivalent to human review, and this document does not claim it is.

## 3. Findings, with disposition

### 3.1 Fixed

| # | Finding | Sev | Disposition |
|---|---|---|---|
| 1 | **`authz-matrix-verify.py` could select, mutate and delete an unrelated real user.** Its "already exists" fallback used `GET /auth/v1/admin/users?email=…` — which **ignores the filter** (measured: a bogus address returned all 19 users) — then took `users[0]`, promoted it to admin and deleted it on teardown | **HIGH** | **Fixed.** Unique address per run; the lookup path is gone entirely; creation failure is now fatal. Teardown moved into a `finally`, verifies all three surfaces, and its result is part of the exit code. |
| 2 | **`setAll`'s second argument (`headers`) was dropped** — it carries cache directives, and `@supabase/ssr` warns a cached response bearing auth cookies can serve one user's session to another | **HIGH** | **Fixed.** The adapter applies them, and every response containing `Set-Cookie` is marked `Cache-Control: private, no-store`. The PKCE callback route does the same. |
| 3 | **`setAll` replaced the response object**, so a second call in one request discarded the first batch of cookies (both reviewers, both rounds) | MED | **Fixed.** Cookies already written are carried across the rebuild. |
| 4 | **`app/admin/users/page.tsx` typed `searchParams` as `string`** — a repeated key arrives as an array and `.trim()` throws | MED | **Fixed.** Typed `string \| string[] \| undefined`, normalised via `firstParam`, with a gate check. |
| 5 | **A user-supplied value was interpolated raw into a PostgREST `or()` filter** in the same page | MED | **Fixed.** `,` `(` `)` `"` are stripped (`.` kept so email searches still work). |
| 6 | **`lib/supabase/server.ts` swallowed every cookie-write failure**, including in Route Handlers and Actions where the write is the point | MED | **Fixed (partly).** Render-time failures stay silent as documented; anything else is now logged. Not rethrown — a render must not break. |
| 7 | **The gate could not have caught the defect it was written for**, and its refresh proof could pass without any token changing | HIGH/MED | **Fixed.** Added: redirect-branch + expired-cookie check; page-level check that the refreshed session reaches the *page*; token-level (not hash-level) refresh assertions; each refresh check mints its own session so rotation cannot make it flaky. |
| 8 | **The committed gate crashed** (`get_body` referenced an undefined global) — reported as HIGH by round 3 | HIGH | **Already fixed** before round 3's report was read (`b4d07de`). The `finally` teardown still ran clean through the crash, which is what that fix was for. |

## 4. What the reviews did not find

Both round-3 reviewers independently confirmed the mechanical conversion: **all 24 server
`createClient()` sites are awaited**; `searchParams` on the users page is awaited and array-safe; the
`getAll`/`setAll` adapter is structurally correct; redirect branches now carry cookies; the
`Cache-Control` sniff applies on every path; **no new sensitive logging**; no unguarded `"use server"`
export; no weakened host validation or rate-limit key. GPT stated explicitly that the previously
reported redirect-cookie loss and repeated-`setAll` loss **"are not present in the displayed
implementation."**
